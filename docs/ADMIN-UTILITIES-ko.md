## 1. 이 문서의 대상

본 패키지의 애플리케이션은 설정 마법사를 마치면 대부분 바로 사용할 수 있습니다. 다만 다음 **두 가지**는 추가 설정이 필요합니다.

| 애플리케이션 | 기능 |
| -- | -- |
| **Outstanding Work Report**(미처리 작업 보고서) | 본인뿐 아니라 테넌트 내 **모든 사용자**의 미처리 작업(변경 지시, 검토, 프로젝트 작업 등)을 나열합니다. |
| **User Settings Manager**(사용자 설정 관리자) | 한 사용자가 작성한 **작업공간 뷰**(열 레이아웃, 필터 등 개인 설정)를 다른 사용자에게 복사합니다. 팀 전체가 동일한 뷰를 공유할 수 있습니다. |

아래 설정 없이 두 애플리케이션을 실행하면 다음 메시지와 함께 중단됩니다.

> **System Admin access required** — 이 애플리케이션은 테넌트의 시스템 관리자로 로그인합니다. 이를 위해서는 Client ID와 Client Secret을 갖는 두 번째 APS 애플리케이션이 필요하지만, 이 두 값이 설정되어 있지 않거나 승인되지 않았습니다.

이 문서는 그 설정 방법을 설명합니다. 약 5분이 소요되며, 한 번만 설정하면 됩니다.

## 2. 왜 "두 번째" APS 애플리케이션이 필요한가

본 패키지의 다른 애플리케이션은 모두 **로그인한 본인으로서** 동작합니다. 본인의 Autodesk 계정으로 로그인하면, 서버가 그 세션을 그대로 테넌트에 전달합니다. 이것이 설정 마법사 1단계에서 작성한 APS 애플리케이션이며, 유형은 `Desktop, Mobile, Single-Page App`입니다.

반면 이 두 유틸리티는 **다른 사용자로서** 동작해야 합니다. 다른 사용자의 미처리 작업을 읽거나 다른 사용자의 계정에 뷰를 기록하는 작업은 본인의 세션으로는 수행할 수 없습니다. 따라서 서버는 먼저 **서버 자신으로** 로그인한 다음, Fusion Manage에 "이 요청은 사용자 X가 보낸 것으로 처리하라"고 지시합니다. Autodesk는 이를 *impersonation*(대행)이라 부르며, **2-legged 인증**에서만 사용할 수 있습니다.

2-legged 인증은 사람이 아니라 **서버의 신원**을 증명하는 방식입니다. 서버가 신원을 증명하는 수단이 바로 **Client Secret**, 즉 애플리케이션 자체의 암호입니다. 1단계의 APS 애플리케이션에는 Client Secret이 아예 없습니다. 해당 유형은 시크릿을 비밀로 유지할 수 없는 사용자 단말용 프로그램을 위해 설계되었기 때문입니다. 그러므로 1단계 애플리케이션을 재사용할 수 없으며, 다른 유형의 애플리케이션을 하나 더 작성해야 합니다.

| | 첫 번째 APS 앱(1단계) | 두 번째 APS 앱(본 문서) |
| -- | -- | -- |
| 유형 | `Desktop, Mobile, Single-Page App` | `Server-to-Server` |
| Client Secret | 없음 | **있음** |
| 로그인 주체 | 본인 | 서버 자신 |
| 사용하는 애플리케이션 | 전체 | Outstanding Work Report, User Settings Manager |
| 마법사 입력란 | Client ID(2단계) | 관리용 Client ID + 관리용 Client Secret(4단계) |

## 3. 두 번째 APS 애플리케이션 작성

1. <https://aps.autodesk.com/myapps/create> 를 열고 Fusion Manage에서 사용하는 것과 **동일한 Autodesk 계정**으로 로그인합니다.
2. **Choose an API** 에서 필요한 API를 선택합니다(기본값 그대로도 무방합니다).
3. **application type** 으로 **`Server-to-Server`** 를 선택합니다.
   이 부분이 중요합니다. Client Secret이 발급되는 유형은 이것뿐입니다. 또한 **작성 후에는 유형을 변경할 수 없습니다.** 잘못 선택한 경우 애플리케이션을 새로 작성해야 합니다.
4. 첫 번째와 구분할 수 있는 **Name** 을 지정합니다. 예: `PLM Extensions (admin)`
5. 이 유형에는 Callback URL이 사용되지 않습니다. 입력란이 표시되더라도 비워 두면 됩니다.
6. **Create app** 을 클릭합니다.
7. 작성된 애플리케이션 페이지에서 다음 두 값을 복사합니다.
   * **Client ID**
   * **Client Secret** — **한 번만** 표시됩니다. 반드시 즉시 복사하십시오. 분실한 경우 같은 페이지에서 다시 발급할 수 있으나, 그 시점에 이전 시크릿은 무효가 됩니다.

### 이 Client ID도 테넌트 허용 목록에 추가

테넌트는 관리자가 승인한 Client ID의 API 호출에만 응답합니다. 이 두 번째 애플리케이션은 별개의 Client ID이므로 첫 번째와 동일하게 등록해야 합니다.

```
https://<테넌트명>.autodeskplm360.net/admin#section=setuphome&tab=general&item=configparams
```

허용된 Client ID 목록(*Forge Client IDs* 또는 *APS Client IDs* 로 표시될 수 있음)을 열고, 첫 번째 **옆에** 새 Client ID를 추가합니다. 첫 번째를 교체하지 마십시오. 둘 다 필요합니다.

## 4. 두 값 입력

1. <http://localhost:8080/setup> 에서 설정 마법사를 엽니다(포트 번호는 Callback URL과 동일합니다).
2. **4단계 — 고급 설정(선택)** 으로 이동한 뒤 [선택 사항 표시]를 클릭합니다.
3. **두 번째** 애플리케이션의 Client ID를 [관리용 Client ID]에 붙여넣습니다.
4. Client Secret을 [관리용 Client Secret]에 붙여넣습니다.
5. [이 자격 증명 테스트]를 클릭합니다.
6. 테스트가 성공하면 6단계로 이동하여 [저장 후 다시 시작]을 클릭합니다.

두 값은 연결 설정 파일(`environment.js`)에 `adminClientId` 및 `adminClientSecret` 으로 기록됩니다. 이 파일을 직접 열 필요는 없습니다.

> 시크릿을 파일에 저장하고 싶지 않다면, 서버를 시작하기 전에 환경 변수 `ADMIN_CLIENT_ID` 와 `ADMIN_CLIENT_SECRET` 을 설정하십시오. 환경 변수가 파일 설정보다 우선하므로 마법사 입력란은 비워 두어도 됩니다.

## 5. 테스트 결과 해석

[이 자격 증명 테스트]는 입력한 두 값으로 Autodesk 인증 서비스에 서버 토큰을 요청합니다. 두 유틸리티가 실제로 보내는 요청과 동일합니다. 테스트로 저장되는 내용은 없으며, 시크릿이 콘솔 창에 출력되거나 브라우저로 반환되지도 않습니다.

| 결과 | 의미 | 조치 |
| -- | -- | -- |
| *이 자격 증명은 유효합니다…* | 서버 토큰이 발급되었습니다. | 저장 후 다시 시작하면 설정이 완료됩니다. |
| *관리용 Client Secret이 입력되지 않았습니다…* | Client Secret이 비어 있습니다. | 입력하십시오. 애플리케이션에 Client Secret이 없다면 유형이 잘못된 것이므로 `Server-to-Server` 로 다시 작성하십시오. |
| *이는 이 서버가 이미 사용자 로그인에 사용 중인 Client ID와 동일합니다…* | 2단계의 Client ID를 붙여넣었습니다. | **두 번째** 애플리케이션의 Client ID를 붙여넣으십시오. |
| *Autodesk가 이 애플리케이션에 대한 서버 토큰 발급을 거부했습니다…* | 애플리케이션은 존재하지만 server-to-server 유형이 아닙니다. | `Server-to-Server` 유형으로 새로 작성하십시오. 기존 애플리케이션의 유형은 변경할 수 없습니다. |
| *Autodesk가 이 값 조합을 승인하지 않았습니다…* | Client ID와 Client Secret이 동일한 애플리케이션의 것이 아니거나 일부가 누락되었습니다. | 같은 애플리케이션 페이지에서 두 값을 다시 복사하십시오. 문자 누락이나 끝의 공백에 유의하십시오. |
| *이 컴퓨터에서 developer.api.autodesk.com에 연결할 수 없습니다…* / *…20초 이내에 응답하지 않았습니다…* | 프록시, 방화벽 또는 인터넷 연결 문제입니다. 입력한 값 자체는 **검증되지 않았습니다**. | 그대로 저장할 수 있습니다. 이후 유틸리티를 직접 실행하여 확인하십시오. |

## 6. 동작 확인

1. 마법사 6단계에서 저장 후 다시 시작하고, 페이지가 돌아올 때까지 기다립니다.
2. 시작 페이지에서 **Outstanding Work Report** 를 실행합니다.
3. *System Admin access required* 화면 대신 사용자와 미처리 작업 목록이 표시되면 성공입니다.

테스트가 성공했는데도 실행되지 않는다면 원인은 대개 다음 두 가지입니다.

* **두 번째 Client ID가 테넌트 허용 목록에 없음** — 3절 마지막 부분을 확인하십시오.
* **본인 사용자가 Fusion Manage의 시스템 관리자가 아님** — 이 유틸리티는 먼저 *본인*이 `Administration [SYSTEM]` 그룹에 속하는지 확인합니다. 두 번째 APS 애플리케이션이 이 권한을 부여하지는 않습니다. 시스템 관리자가 아닌 경우에는 *This feature requires system admin privileges* 가 표시되며, 이는 본 문서가 다루는 메시지와 다릅니다.

## 7. 보안 유의 사항 (반드시 읽어 주십시오)

Client Secret은 단순한 편의 설정이 아닙니다. Client ID와 Client Secret을 확보한 사람은 이 서버를 통해 **테넌트의 모든 사용자로서** 데이터를 읽고 쓸 수 있습니다. 해당 사용자가 로그인할 필요도 없고, 대화형 로그인 기록도 남지 않습니다.

운영 지침:

* **두 유틸리티를 실제로 사용하는 기간에만 설정하십시오.** 4단계의 두 입력란을 비우고 저장하면 설정이 제거됩니다.
* **시크릿은 암호처럼 취급하십시오.** 채팅, 문의 티켓, 스크린샷, 메일에 붙여넣지 마십시오.
* **공용 PC에는 설정하지 마십시오.** 이 서버는 본인 PC에서 실행하는 것을 전제로 합니다. 공용 장비나 데모 장비에서는 4절의 환경 변수 사용을 권장합니다. 전원을 끄면 시크릿이 남지 않습니다.
* **`environment.js` 를 커밋하지 마십시오.** 시크릿이 평문으로 포함됩니다.
* **유출된 경우 즉시 무효화하십시오.** APS 애플리케이션 페이지에서 Client Secret을 다시 발급하면 이전 시크릿은 즉시 무효가 됩니다. 애플리케이션 자체를 삭제해도 됩니다.
* 대행으로 수행된 작업은 본인이 아니라 **대행 대상 사용자 이름**으로 Fusion Manage에 기록된다는 점도 유의하십시오.
