## 1. この文書の対象

本パッケージのアプリケーションは、セットアップ ウィザードを完了すればそのまま使用できます。ただし、次の **2 つ**だけは追加の設定が必要です。

| アプリケーション | 機能 |
| -- | -- |
| **Outstanding Work Report**（未処理作業レポート） | 自分だけでなく、テナント内の**全ユーザ**の未処理作業（変更オーダ、レビュー、プロジェクト タスクなど）を一覧表示します。 |
| **User Settings Manager**（ユーザ設定マネージャ） | あるユーザが作成した**ワークスペース ビュー**（列レイアウトやフィルタなどの個人設定）を、他のユーザにコピーします。チーム全体で同じビューを共有できます。 |

以下の設定を行わずにこれらを起動すると、次のメッセージで停止します。

> **System Admin access required** — このアプリケーションはテナントのシステム管理者としてログインします。そのためには Client ID と Client Secret を持つ 2 つ目の APS アプリケーションが必要ですが、この 2 つの値が未設定であるか、受け付けられませんでした。

本書はその設定手順を説明します。所要時間は約 5 分、設定は一度だけです。

---

## 2. なぜ「2 つ目」の APS アプリケーションが必要なのか

本パッケージの他のアプリケーションは、すべて**ログインしたご本人として**動作します。ご自身の Autodesk アカウントでログインし、サーバはそのセッションをそのままテナントに渡します。これがセットアップ ウィザードの手順 1 で作成した APS アプリケーションで、種類は `Desktop, Mobile, Single-Page App` です。

一方、この 2 つのユーティリティは**他のユーザとして**動作する必要があります。他のユーザの未処理作業を読み取ったり、他のユーザのアカウントにビューを書き込んだりする操作は、ご自身のセッションでは実行できません。そのためサーバは、まず**サーバ自身として**ログインし、そのうえで Fusion Manage に「この要求はユーザ X が行ったものとして扱ってください」と指示します。これを Autodesk では *impersonation*（代理実行）と呼び、**2-legged 認証**でのみ利用できます。

2-legged 認証は、人ではなく**サーバの身元**を証明する仕組みです。サーバが身元を証明する手段が **Client Secret**、すなわちアプリケーション自身のパスワードです。手順 1 の APS アプリケーションには Client Secret が存在しません。この種類は、シークレットを秘密のまま保持できないユーザ端末上のプログラム向けに設計されているためです。したがって手順 1 のアプリケーションを流用することはできず、別の種類のアプリケーションをもう 1 つ作成する必要があります。

| | 1 つ目の APS アプリ（手順 1） | 2 つ目の APS アプリ（本書） |
| -- | -- | -- |
| 種類 | `Desktop, Mobile, Single-Page App` | `Server-to-Server` |
| Client Secret | なし | **あり** |
| ログインする主体 | ご本人 | サーバ自身 |
| 使用するアプリケーション | すべて | Outstanding Work Report、User Settings Manager |
| ウィザードの入力欄 | Client ID（ステップ 2） | 管理用 Client ID + 管理用 Client Secret（ステップ 4） |

## 3. 2 つ目の APS アプリケーションを作成する

1. <https://aps.autodesk.com/myapps/create> を開き、Fusion Manage で使用しているものと**同じ Autodesk アカウント**でサインインします。
2. **Choose an API** で必要な API を選択します（既定のままで問題ありません）。
3. **application type** で **`Server-to-Server`** を選択します。
   ここが重要です。Client Secret が発行されるのはこの種類だけです。また、**作成後に種類を変更することはできません**。誤った種類を選んだ場合は、アプリケーションを作り直す必要があります。
4. 1 つ目と区別できる **Name** を付けます（例: `PLM Extensions (admin)`）。
5. この種類では Callback URL は使用しません。入力欄が表示された場合は空のままで構いません。
6. **Create app** をクリックします。
7. 作成されたアプリケーションのページで、次の 2 つの値をコピーします。
   * **Client ID**
   * **Client Secret** — 表示されるのは**この 1 回だけ**です。必ずその場でコピーしてください。紛失した場合は同じページで再発行できますが、その時点で旧シークレットは無効になります。

### この Client ID もテナントの許可リストに追加する

テナントは、管理者が承認した Client ID からの API 呼び出しにのみ応答します。この 2 つ目のアプリケーションは別の Client ID なので、1 つ目と同様に登録が必要です。

```
https://<テナント名>.autodeskplm360.net/admin#section=setuphome&tab=general&item=configparams
```

許可された Client ID の一覧（*Forge Client IDs* または *APS Client IDs* と表示される場合もあります）を開き、1 つ目の**隣に**新しい Client ID を追加します。1 つ目を置き換えないでください。両方が必要です。

---

## 4. 2 つの値を入力する

1. <http://localhost:8080/setup> でセットアップ ウィザードを開きます（ポート番号は Callback URL と同じものです）。
2. ステップ **4 — 任意の詳細設定**に進み、［選択可能な設定を表示］をクリックします。
3. **2 つ目**のアプリケーションの Client ID を［管理用 Client ID］に貼り付けます。
4. Client Secret を［管理用 Client Secret］に貼り付けます。
5. ［この認証情報をテスト］をクリックします。
6. テストが成功したら、ステップ 6 に進み［保存して再起動］をクリックします。

2 つの値は接続設定ファイル（`environment.js`）に `adminClientId` および `adminClientSecret` として書き込まれます。このファイルを直接開く必要はありません。

> シークレットをファイルに保存したくない場合は、サーバ起動前に環境変数 `ADMIN_CLIENT_ID` と `ADMIN_CLIENT_SECRET` を設定してください。環境変数がファイルの設定より優先されるため、ウィザードの入力欄は空のままで構いません。

---

## 5. テスト結果の読み方

［この認証情報をテスト］は、入力された 2 つの値を使って Autodesk 認証サービスにサーバ トークンを要求します。これは 2 つのユーティリティが実際に行う要求と同じものです。テストによって設定が保存されることはなく、シークレットがコンソール ウィンドウに出力されることも、ブラウザに送り返されることもありません。

| 結果 | 意味 | 対処 |
| -- | -- | -- |
| *この認証情報は有効です…* | サーバ トークンが発行されました。 | 保存して再起動してください。設定は完了です。 |
| *管理用 Client Secret が入力されていません…* | Client Secret が空です。 | 入力してください。アプリケーションに Client Secret が存在しない場合は種類が誤っています。`Server-to-Server` で作成し直してください。 |
| *これは、このサーバがユーザのログインにすでに使用している Client ID と同じです…* | ステップ 2 の Client ID を貼り付けています。 | **2 つ目**のアプリケーションの Client ID を貼り付けてください。 |
| *Autodesk はこのアプリケーションに対するサーバ トークンの発行を拒否しました…* | アプリケーションは存在しますが、種類が server-to-server ではありません。 | `Server-to-Server` で新規に作成してください。既存アプリケーションの種類は変更できません。 |
| *Autodesk はこの値の組み合わせを受け付けませんでした…* | Client ID と Client Secret が同じアプリケーションのものではないか、どちらかが不完全です。 | 同じアプリケーションのページから両方をコピーし直してください。文字の欠落や末尾の空白にご注意ください。 |
| *このコンピュータから developer.api.autodesk.com に接続できませんでした…* / *…20 秒以内に応答がありませんでした…* | プロキシ、ファイアウォール、またはネットワーク未接続です。入力値自体は**検証されていません**。 | そのまま保存できます。あとで実際にユーティリティを起動して確認してください。 |

---

## 6. 動作確認

1. ウィザードのステップ 6 で保存して再起動し、ページが戻るまで待ちます。
2. ランディング ページから **Outstanding Work Report** を起動します。
3. *System Admin access required* の画面ではなく、ユーザと未処理作業の一覧が表示されれば成功です。

テストが成功したのに起動しない場合、原因はほぼ次の 2 つのいずれかです。

* **2 つ目の Client ID がテナントの許可リストに登録されていない** — 手順 3 の末尾をご確認ください。
* **ご自身のユーザが Fusion Manage のシステム管理者ではない** — これらのユーティリティは、まず*ご自身*が `Administration [SYSTEM]` グループに属しているかを確認します。2 つ目の APS アプリケーションはこの権限を付与するものではありません。システム管理者でない場合に表示されるのは *This feature requires system admin privileges* で、本書が扱うメッセージとは別のものです。

## 7. セキュリティに関する注意（必ずお読みください）

Client Secret は単なる利便性のための設定ではありません。Client ID と Client Secret を入手した者は、このサーバを通じて、**テナント内の任意のユーザとして**データの読み取りと書き込みを実行できます。そのユーザがログインする必要はなく、対話的なログインの記録も残りません。

運用上の指針:

* **これら 2 つのユーティリティを実際に使用する期間だけ設定してください。** ステップ 4 の両方の入力欄を空にして保存すれば、設定は削除されます。
* **シークレットはパスワードと同様に扱ってください。** チャット、問い合わせ票、スクリーンショット、メールに貼り付けないでください。
* **共有 PC には設定しないでください。** 本サーバはご自身の PC での実行を想定しています。共有機やデモ機では、手順 4 の環境変数の利用を推奨します。電源を切ればシークレットは残りません。
* **`environment.js` をコミットしないでください。** シークレットが平文で含まれます。
* **漏洩した場合は速やかに無効化してください。** APS のアプリケーション ページで Client Secret を再発行すると旧シークレットは即座に無効になります。アプリケーション自体を削除しても構いません。
* 代理実行された操作は、ご自身ではなく**代理対象のユーザ名**で Fusion Manage に記録される点にもご留意ください。
