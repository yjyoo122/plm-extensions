# PLM Extensions — インストールと利用の手引き（日本語）

English: [INSTALL-en.md](INSTALL-en.md) · 한국어: [INSTALL-ko.md](INSTALL-ko.md)

---

## 1. これは何か

本パッケージは、お客様の **Autodesk Fusion Manage テナント**上で動作するカスタム Web アプリケーション（User Experiences）群です。PLM ポータル、ワークスペース ナビゲータ、各種 BOM（部品表）エディタ、ダッシュボード、および管理者向けユーティリティが含まれます。**お使いの PC 上**で小さな Web サーバとして動作し、ブラウザで `http://localhost:8080` を開いて利用します。データのやり取りは Fusion Manage の REST API 経由です。利用は無償です。レンタル サーバも、どこかにホストされるサービスもありません。PLM データは「お使いの PC」と「お客様のテナント」の間だけを流れ、Fusion Manage の外部には一切保存されません。

> 本ソフトウェアは <ins>Autodesk の公式製品ではありません</ins>。無保証の現状有姿（as is）で提供されるコミュニティ製のソース コードです。詳細はリポジトリの `README.md` の免責事項をご確認ください。

## 2. 事前に必要なもの

| 必要なもの | 不要なもの |
| -- | -- |
| ログインできる Fusion Manage テナント（Autodesk アカウント） | 事前のインストール作業（実行に必要な Node.js ランタイムを含め、すべてパッケージに含まれています） |
| テナントの［一般設定］でクライアント ID を許可リストに登録する権限（または代行してくれる管理者） | コマンド プロンプト／ターミナル操作（コマンド入力は一切ありません） |
| Windows 11 の PC と ブラウザ（Chrome または Edge） | プログラミングの知識、`.js` ファイルの手編集 |
| 所要時間 **約 10 分** | 費用（使用する Autodesk Platform Services の API は無償です） |

**用語のご説明**

| 用語 | 平たく言うと |
| -- | -- |
| **テナント (tenant)** | 自社の Fusion Manage サイトのこと。ログイン URL の先頭部分です。`https://acme.autodeskplm360.net` ならテナント名は `acme` です。 |
| **APS** | Autodesk Platform Services。本ツールがログインを行えるように「アプリケーション」を登録する Autodesk の開発者サイトです。 |
| **クライアント ID (Client ID)** | 手順 1 で作成する APS アプリケーションを識別する長い文字列（例: `k7QsX2f9...`）。パスワードではなく、秘密情報でもありません。 |
| **コールバック URL (Callback URL)** | ログイン後にブラウザが戻される URL。APS 側と本ツール側で**完全に一致**している必要があります。 |
| **ワークスペース** | Fusion Manage のデータ領域。アイテム、変更オーダ、プロジェクトなど。 |
| **コンソール ウィンドウ** | 起動時に現れる黒い文字だけのウィンドウ。これ自体がアプリ本体です（手順 3 参照）。 |

## 3. 手順 1 — APS アプリケーションを作成する

1. ブラウザで <https://aps.autodesk.com/myapps/create> を開きます。
2. Fusion Manage で使用しているものと**同じ Autodesk アカウント**でサインインします。
3. ［Choose an API］では、既定の選択のままで構いません。
4. アプリケーションの種類は必ず **`Desktop, Mobile, Single-Page App`** を選択します。
   ここは重要です。「Web App」や「Server-to-Server」を選ぶと、後のログインで **401** エラーになります。
5. ［Name］［Description］は任意です。例: `PLM Extensions (local)`。
6. ［Callback URL］には、次の文字列を**一字一句そのまま**入力します。

   ```
   http://localhost:8080/callback
   ```

   下表の間違いが非常に多いので、1 文字ずつご確認ください。

   | よくある入力ミス | 結果 |
   | -- | -- |
   | `https://localhost:8080/callback`（https） | `400 - Invalid redirect_uri` |
   | `http://localhost:8080/callback/`（末尾のスラッシュ） | `400 - Invalid redirect_uri` |
   | `http://127.0.0.1:8080/callback` | `400 - Invalid redirect_uri` |
   | `http://localhost:3000/callback`（ポート番号違い） | `400 - Invalid redirect_uri` |

7. ［Create app］をクリックします。
8. 表示された画面で **Client ID** をコピーします。この画面は**閉じずに残しておいてください**。手順 2 と手順 4 の 2 か所で使用します。

---

## 4. 手順 2 — クライアント ID をテナントの許可リストに登録する

未登録のアプリケーションからのログインはテナント側で拒否されます。クライアント ID の登録は最初の 1 回だけ必要です。

1. Fusion Manage テナントにログインします。
2. 右上の歯車アイコンから［**管理**（Administration）］→［**一般設定**（General Settings）］を開きます。
3. 許可するクライアント ID を登録する設定項目を探します（テナントのバージョンによっては *Forge Client IDs* / *APS Client IDs* と表示されます）。
4. 手順 1 でコピーしたクライアント ID を貼り付けます。既存の ID がある場合は**削除せず**、改行して追記してください。
5. 保存します。

> 管理者権限をお持ちでない場合は、クライアント ID を Fusion Manage 管理者に送り、登録を依頼してください。この作業以外で管理者権限が必要になるのは、第 9 章に記載の管理ユーティリティのみです。

## 5. 手順 3 — 展開して起動する

1. パッケージの `.zip` ファイルをダウンロードします。
2. 右クリック →［**すべて展開**］で、任意の場所に展開します。**デスクトップで問題ありません。**
   可能であれば OneDrive の同期対象フォルダは避けてください。同期処理が実行中のファイルをロックすることがあります。
3. 展開したフォルダを開き、**`Start.cmd`** をダブルクリックします。
4. **黒いコンソール ウィンドウ**が開き、文字が流れます。

   > **重要:** この黒いウィンドウが**アプリケーション本体**です。エラーでも消し忘れでもありません。アプリを使用している間は**閉じないでください**。閉じるとサーバが停止し、ブラウザのタブも動作しなくなります。
   >
   > 最小化するのは問題ありません。停止したい場合を除き、ウィンドウ内で `Ctrl` + `C` を押さないでください。

5. 初回起動時は、準備のため 1〜2 分ほど無反応に見えることがあります。異常ではありません。
6. 既定のブラウザが自動的に `http://localhost:8080` を開きます。開かない場合は、ブラウザでこの URL を直接入力してください。

ここで Windows のセキュリティ警告が表示された場合は、第 9 章のトラブルシューティング（SmartScreen の行）をご覧ください。

## 6. 手順 4 — セットアップ ウィザード

接続設定が未入力の状態で初回起動すると、ブラウザにはランディング ページではなく **セットアップ ウィザード**（`http://localhost:8080/setup`）が表示されます。

上から順に入力します。

| 項目 | 入力する内容 |
| -- | -- |
| **テナント** | URL 全体ではなく、テナント名だけを入力します。`https://acme.autodeskplm360.net` なら `acme`。 |
| **クライアント ID** | 手順 1 でコピーした値を貼り付けます。 |
| **コールバック URL** | `http://localhost:8080/callback` のままにします。APS アプリケーション側と完全に一致している必要があります。 |
| **テーマ** | `dark`（ダーク）または `light`（ライト）。後から変更できます。個別の URL に `&theme=light` を付けて切り替えることも可能です。 |
| **言語** | `English` / `日本語 (ja)` / `한국어 (ko)`。ユーザ インタフェースの既定言語になります。 |

続いて、次の操作を行います。

1. ［**ワークスペースを検出**（Discover workspaces）］をクリックします。ウィザードがテナントにサインインし（通常の Autodesk ログイン画面が表示されるので承認してください）、テナントのワークスペース一覧を読み取って、**ワークスペース ID**（数値）を自動で設定します。
   * テナントに存在しないワークスペースは空欄のままになります。これは正常な動作です。
   * この ID は、各アプリがアイテム、変更オーダ、プロジェクトなどを参照するために使用します。ID が未設定だと、アプリ内の一覧が空のままになります。
2. 検出結果を確認します。値が分かっている場合は、ウィザード上で個別に修正できます。
3. ［**保存**］をクリックします。

ウィザードが入力内容を `environment.js` および `settings/custom.js` に書き込み、**アプリケーションが自動的に再起動します**。コンソール ウィンドウに再起動のメッセージが流れますが、正常な動作ですので閉じないでください。数秒後にブラウザを再読み込みすると、メイン ページが表示されます。

> テナント、テーマ、言語の変更や、ワークスペース検出のやり直しは、いつでも `http://localhost:8080/setup` から実行できます。

## 7. 手順 5 — 使ってみる

* **ランディング ページ — `http://localhost:8080`**
  利用可能な全アプリケーションの一覧と概要、およびアプリ個別の追加設定手順が記載されています。初回はここから始めてください。
* **スタート メニュー — `http://localhost:8080/start`**
  特定の PLM レコードを起点としないアプリケーションをまとめたランチャーです（たとえば各 BOM エディタはアイテムから起動するため、ここには表示されません）。
* 単一レコードを対象とするアプリケーションは、通常 Fusion Manage 側から、または URL にレコードを指定して起動します。詳細はランディング ページのアプリごとの説明をご覧ください。

### 後から言語を切り替える

どちらの方法でも即座に反映されます。

1. **ページ ヘッダの言語セレクタ** — `English` / `日本語` / `한국어` から選択します。ページが 1 回再読み込みされ、選択内容はブラウザに記憶されるため、以降はすべてのアプリに適用されます。
2. **任意の URL** に `?uilang=ja`（日本語）、`?uilang=ko`（韓国語）、`?uilang=en`（英語）を付けます。例:

   ```
   http://localhost:8080/start?uilang=ja
   ```

   URL に既に `?` が含まれている場合は、`&uilang=ja` としてください。

未翻訳のテキストは英語のまま表示されます。動作に支障はなく、いつでも `?uilang=en` で英語に戻せます。

## 8. 終了と再起動

| 目的 | 操作 |
| -- | -- |
| **終了する** | 黒いコンソール ウィンドウを閉じる（**×**）か、ウィンドウ内をクリックして `Ctrl` + `C` を押します。 |
| **再起動する** | もう一度 `Start.cmd` をダブルクリックします。 |
| 画面が固まった場合 | 終了 → 再起動 → ブラウザを再読み込み（`F5`）します。 |

終了してもデータは失われません。PC 側には何も保存されず、すべてのデータは Fusion Manage テナントにあります。

なお、同僚に使わせるために PC を起動したままにしておく必要はありません。このサーバはご自身専用です。同僚の方には、それぞれの PC に導入していただいてください。

## 9. トラブルシューティング

| 症状 | 原因 | 対処 |
| -- | -- | -- |
| ログイン時に `400 - Invalid redirect_uri` | APS アプリケーションの**コールバック URL** と、サーバが使用する `redirectUri` が 1 文字でも異なっています。末尾のスラッシュ、`http` と `https` の違い、`localhost` と `127.0.0.1` の違い、ポート番号違いが典型例です。 | <https://aps.autodesk.com/myapps> で該当アプリを開き、コールバック URL を `http://localhost:8080/callback` に正確に設定します。その後、セットアップ ウィザード側の値も一致していることを確認します。 |
| ログイン後に **401 Unauthorized** | APS アプリケーションの種類が誤っているか、クライアント ID がテナントの許可リストに未登録です。 | APS アプリの種類が **Desktop, Mobile, Single-Page App** であることを確認します（作成後に種類は変更できないため、誤っている場合は作り直します）。あわせて手順 2 を再確認します。 |
| ログイン画面が表示されるが、繰り返しログイン画面に戻る | `localhost` の Cookie がブロックされている、または当該テナントへのアクセス権がないアカウントでサインインしています。 | `localhost` の Cookie を許可し、Fusion Manage で使用しているアカウントでサインインします。 |
| コンソールに `EADDRINUSE`／`address already in use` と表示される、ページが開かない | **ポート 8080 が他のプログラムに使用されています**（本アプリの二重起動、他の開発ツールなど）。 | 重複して開いているコンソール ウィンドウを閉じて再試行します。他のプログラムが恒常的に占有している場合は、セットアップ ウィザードでコールバック URL を空きポート（例: `http://localhost:8081/callback`）に変更し、**APS アプリケーション側のコールバック URL も同じ値に**変更します。 |
| `Start.cmd` のダブルクリック時に「**WindowsによってPCが保護されました**」（SmartScreen） | ダウンロードした `.cmd` ファイルを Windows が認識できないためです。 | ［詳細情報］→［実行］をクリックします。事前に回避したい場合は、展開前の `.zip` を右クリック →［プロパティ］→［**許可する**（ブロックの解除）］にチェック → OK してから展開します。 |
| ウイルス対策ソフトが `Start.cmd` をブロック／削除する、Windows ファイアウォールが確認を求める | 企業のセキュリティ ソフトは、スクリプトやローカル サーバを不審な動作とみなすことがあります。 | 当該ファイルを許可し、ファイアウォールでは「**プライベート ネットワーク**」のみ許可します。社内ポリシー上許可できない場合は、展開先フォルダの除外登録を情報システム部門にご依頼ください。 |
| アプリ内のワークスペース一覧（アイテム、変更オーダなど）が**空**になる | ワークスペース ID が未設定または誤っています。検出を実行していないか、そのワークスペースがテナントに存在しません。 | `http://localhost:8080/setup` を開き、［ワークスペースを検出］を再実行します。テナントに本当に存在しないワークスペースは空欄のままで構いません。そのワークスペースを使うアプリだけが動作せず、他のアプリには影響しません。 |
| BOM ツリーの表示が空になる、またはエラーになる（BOM 系アプリ全般） | これらのアプリは、リポジトリの `README.md` に記載のとおり、`Tree Navigator` という名前の **BOM ビュー**をテナント側に必要とします。新規テナントには標準で用意されますが、既存テナントにはありません。 | Fusion Manage のアイテム ワークスペースで、名前が正確に `Tree Navigator` の BOM ビューを作成し、列は **`Descriptor`、`Number`、`Quantity` の 3 つのみ**とします。 |
| 「権限がありません」と表示される、管理系データが空になる | 一部のアプリケーションは PLM 側の権限を必要とします。特に **Tenant Insights** はテナントのシステム ログを参照するため、**システム管理者**権限が必要です。その他の管理ユーティリティにも管理者権限が必要です。 | テナント管理者に実行を依頼するか、必要なロールの付与を依頼してください。 |
| **Outstanding Work Report** または **User Settings Manager** が起動しない | この 2 つのユーティリティは他ユーザへの成りすまし（impersonation）を行うため、2-legged 認証が必要です。すなわち、**クライアント シークレットを持つ別の APS アプリケーション**が追加で必要になります。 | 2 つ目の APS アプリケーション（クライアント シークレットが発行される server-to-server 型）を作成し、そのクライアント ID とシークレットを、セットアップ ウィザードの詳細設定で `adminClientId` / `adminClientSecret` として入力します。この 2 つのユーティリティを実際に使う場合のみ設定してください。クライアント シークレットは機密情報です。パスワードと同様に扱い、他者と共有しないでください。 |
| メニューに表示されないアプリがある | スタート メニューの内容と、有効化するアプリケーションは設定で変更できます。 | `settings/custom.js` の `exports.menu`、`exports.server.servicesEnabled` の設定変更となります。本パッケージの管理担当者にご相談ください。 |
| 日本語／한국어 に切り替えても、一部が英語のまま | 正常な動作です。翻訳は辞書方式で、対訳は順次拡充されます。未翻訳の文字列は英語のまま表示されます（フォールバック）。 | 対処不要です。辞書の拡充方法は [I18N.md](I18N.md)（英語）をご覧ください。 |
| PLM のデータ値まで翻訳されてしまう（例: 名称が「New」のアイテムが「新規」と表示される） | 翻訳は文字列全体の完全一致で判定するため、UI ラベルと同一の値を持つデータも翻訳対象になります。 | [I18N.md](I18N.md) の「false positives」の節をご覧ください。該当箇所を 1 行の指定で翻訳対象から除外できます。本パッケージの管理担当者にご依頼ください。 |

## 10. 新しいバージョンへの更新

設定は 2 つのファイルにのみ保存されています。この 2 つを引き継げば、設定はそのまま維持できます。

1. アプリを**終了**します（コンソール ウィンドウを閉じる）。
2. 新しい `.zip` をダウンロードし、**別の新しいフォルダ**に展開します。既存フォルダへの上書き展開は行わないでください。
3. **旧**フォルダから次の 2 ファイルを**新**フォルダにコピーし、上書きします。

   | ファイル | 内容 |
   | -- | -- |
   | `environment.js` | テナント、クライアント ID、コールバック URL、テーマ、言語 |
   | `settings/custom.js` | ワークスペース ID、その他のカスタム設定 |

   複数テナントを使い分けている場合は、`environments/` フォルダ全体と、`settings/` に追加したファイルもコピーしてください。
4. **新**フォルダの `Start.cmd` をダブルクリックします。
5. ランディング ページが表示されること、アプリが 1 つ正常に開くことを確認します。
6. 旧フォルダは 1 週間ほど残しておき、問題がなければ削除します。

> 設定の構造が変更されたリリースでは、セットアップ ウィザードがその旨を通知し、`settings/custom.js` を再生成できます。［ワークスペースを検出］の再実行はいつ行っても安全です。
